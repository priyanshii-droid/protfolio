Section 01 • The Catalyst

The Problem: Missing Context in Digital Banking

Digital banking in India and across the world has achieved remarkable technological speed. Payments happen in milliseconds over UPI and IMPS. Yet, as the underlying pipes grew faster, the human experience grew colder and more disorienting.

“Did I get hacked? Who is 'POS-RET-BLR-092'? I don't remember spending 1,420 rupees on Tuesday.”

— A family member's panic over a cryptic bank SMS statement

This incident was not an isolated edge case. Observing friends, parents, and elderly relatives interact with banking applications revealed a fundamental truth: banking applications display raw database records rather than meaningful human context.

We diagnosed four distinct dimensions where modern digital banking systematically fails its users:

1

Cryptic Ledgers

Merchant descriptors like PYMT/29381/POS-KA terrify users. Instead of showing "Coffee at Third Wave with Tanvi", banking apps dump payment gateway metadata.

2

Isolated Silos

Savings, fixed deposits, credit cards, and investments live in fragmented tabs. There is no unified storyline explaining how today's spending impacts next week's commitments.

3

Anxiety Error Codes

When a server times out, users see ERROR: 9924-GATEWAY_TIMEOUT. It fails to answer the only question that matters: Is my money safe or lost?

4

The Accessibility Chasm

For elderly citizens or first-time digital users, complex multi-level menus and financial jargon act as an intimidating barrier rather than an empowering tool.

Section 02 • Empathy & Discovery

User Research: What People Actually Need

During the initial hours of the hackathon, before writing a single line of backend logic, we sketched out user personas and conducted quick informal interviews with hackathon mentors and peers. The insights completely reshaped our product direction:

Insight 1: People don't want spreadsheets; they want reassurance. When a student opens their banking app, they aren't looking to calculate standard deviations. They want to know: "Can I afford to eat out with friends this weekend without running out of money before my monthly allowance arrives?"

Insight 2: Voice is the great equalizer. Many non-tech-savvy users avoid typing in search boxes or browsing nested accordions. Speaking naturally in their native cadence ("Did my scholarship come through yet?") provides a 10x friendlier entry point.

Insight 3: The power of a 'Digital Twin'. People find financial planning stressful because it feels theoretical. Being able to run simulations—such as "What happens if I make this one-time purchase today?"—replaces dread with informed confidence.

Section 03 • Systems Architecture

How Saarthi Works: The Context Pipeline

Saarthi is structured as a multi-tier contextual intelligence layer running between the raw banking core and the user interface. Its purpose is to ingest ambiguous queries and disparate ledger entries, synthesize them with user memory and heuristics, and output clear, conversational guidance.

Layer 1

Input Channels

Captures natural voice speech via Web Speech API or typed conversational queries.

Layer 2 • Core

Context Resolver

Extracts financial intent, time horizons, and entity references (merchants, categories, friends).

Layer 3

Clean Statement Ledger

Maps raw, cryptic bank statements to recognizable merchant names, categories, and subscriptions.

Layer 4 • Output

Calm Insights

Delivers reassuring, plain-English summaries and voice explanations instead of cold error codes.

A key engineering decision was separating computational verification from natural language explanation. In financial tools, AI models should not do calculations where exact numbers matter. Saarthi calculates all numbers directly in code, using the AI model solely to understand questions, retrieve relevant context, and explain financial insights in plain, reassuring English.

Section 04 • Product Walkthrough

The Implemented Interface & Screen Flow

Here is the complete walkthrough of the Saarthi working prototype, illustrating how each user flow bridges the gap between raw financial mechanics and human empathy.

Flow 01 • Entry

Calm, Welcoming Onboarding

A minimalist, reassuring login interface that prioritizes peace of mind over aggressive security warnings, easing initial user apprehension.

Flow 02 • Core Experience

Contextual Home Hub

Replaces cluttered multi-column menus with a clean breakdown of available funds, daily safe-to-spend limits, and immediate action cards.

Flow 03 • Voice & Text

Conversational Audio Companion

"Talk to Saarthi" allows users to ask questions out loud in conversational language and receive immediate spoken and visual explanations.

Flow 04 • Expense Context

Hisaab: Human Daily Breakdown

Groups expenditures into real-life human contexts (hostel, chai, study materials) rather than cryptic point-of-sale merchant codes.

Flow 05 • The Ledger

Context-Enriched Ledger

Every transaction card includes verified merchant identities, locations, timestamps, and a one-click "Explain this transaction" button.

Flow 06 • Simulation

The Financial Digital Twin

A predictive sandbox that simulates how upcoming decisions will affect personal cash flow weeks into the future, eliminating guesswork.

Flow 07 • Trust & Security

Transparent Security Audit

Plain-English security verification and activity logs that inform the user exactly which services accessed data and why.

Flow 08 • Projection

Financial Time Machine

Interactive timeline sliders that project balance trajectories based on recurring subscriptions and historical spending cadence.

Section 05 • Honesty in Engineering

Implementation Reality vs Future Roadmap

In keeping with the philosophy of "Still Becoming", I believe in absolute engineering honesty. Hackathon prototypes demonstrate possibility; production systems require rigorous iteration. Here is an honest breakdown of what was built during the 36-hour sprint versus the architectural roadmap.

✓ Implemented in 36h

The Working Prototype

  • ✦ Context Resolver Engine: Rule-based and semantic extraction of financial queries into structured intent objects.
  • ✦ Simulated Banking Ledger: Mock database of 200+ multi-category transactions with realistic UPI descriptor strings.
  • ✦ Voice Interface Integration: Real-time microphone capture and speech-to-text synthesis via Web Speech API.
  • ✦ Interactive Dashboard: Fully responsive interface connecting the Hisaab, Digital Twin, and Ledger screens.
  • ✦ Reassurance Generator: Plain-English error code translator converting cryptic HTTP/gateway errors into actionable steps.
✦ Architectural Roadmap

Future Engineering Horizons

  • ✦ India Account Aggregator (AA) Integration: Live consent-based financial data fetching across multiple banks via RBI-regulated AA pipes.
  • ✦ On-Device Local SLM: Running small quantized models locally on the device (WebLLM / ONNX) so sensitive banking data never leaves the handset.
  • ✦ Multilingual Voice Models: Fine-tuned regional speech engines supporting conversational Hindi, Gujarati, and Marathi for non-English speakers.
  • ✦ Automated Dispute Resolver: One-tap automated chargeback and grievance filing with auto-attached merchant receipts.
  • ✦ Zero-Knowledge Audit Vault: Cryptographic verification ensuring that banking assistants cannot view user balances in plaintext on centralized servers.
